# 손주약방 RAG 의약품 데이터 — 전처리 · 등록 · 갱신 매뉴얼

> 이 폴더(`backend/knowledge/`)는 **손주약방 AI(RAG)가 참고하는 의약품 지식 창고**입니다.
> 개발자가 아니어도, 정해진 양식(표준 JSONL)만 지키면 자료를 계속 추가·수정할 수 있습니다.

---

## 0. 한눈에 보는 전체 흐름

```
 [원본 자료]            [전처리 도구]              [지식 창고]            [AI 반영]
 엑셀/CSV, 식약처    →  drug_preprocess.py   →   knowledge/*.jsonl  →  POST /api/rag/reload
 API(JSON/XML)          (자동 변환+검증)          (표준 형식 저장)        (바뀐 것만 임베딩)
```

1. 원본 자료를 **CSV(엑셀)** 또는 식약처 API 파일로 준비
2. **전처리 도구**로 표준 형식(`.jsonl`)으로 자동 변환 + 누락/중복 검사
3. 변환 결과를 이 폴더(`knowledge/`)에 저장
4. 서버에 **`POST /api/rag/reload`** 한 번 호출 → 재시작 없이 즉시 반영

## 1. 표준 데이터 형식

### 1-1. 파일 형식: **JSONL** 을 사용합니다
- `.jsonl` = "한 줄에 약 1건"을 적는 형식입니다. (JSON Lines)
- **CSV, JSONL 중 무엇으로 작업해도 됩니다.** 익숙한 엑셀(CSV)로 만들고,
  전처리 도구가 `.jsonl`로 바꿔 줍니다. (JSONL이 최종 저장 형식)
- ❌ 일반 `.json`(통짜 배열)은 한 건만 틀려도 전체가 깨지므로 **최종본은 JSONL** 권장.

### 1-2. 항목(필드) 표준

| 필드 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `source` | **필수** | 출처(신뢰성 근거) | `식약처 의약품 제품 허가정보` |
| `text` | 조건부 | AI가 검색하는 본문. **비워두면 아래 항목들로 자동 생성** | `아모디핀정 5mg(암로디핀...). 효능...` |
| `drug_name` | 권장 | 의약품명(품목명) | `아모디핀정 5mg` |
| `ingredient` | 권장 | 성분명 | `암로디핀베실산염` |
| `amount` | 선택 | 함량/용량 | `5mg` |
| `effect` | 권장 | 효능·효과 | `고혈압, 협심증 치료` |
| `usage` | 선택 | 복용법/용법용량 | `1일 1회 1정` |
| `caution` | 권장 | 주의사항 | `자몽주스와 함께 복용 금지` |
| `side_effect` | 선택 | 부작용 | `얼굴 부종, 어지러움` |
| `storage` | 선택 | 보관법 | `실온(1~30도) 보관` |
| `interaction` | 선택 | 상호작용 | `와파린과 병용 주의` |
| `appearance` | 선택 | 생김새/성상 | `흰색 원형 정제` |
| `category` | 선택 | 분류(기본 `drug`) | `drug`, `diabetes`, `supplement` |
| `id` | 선택 | 고유 키(**갱신·중복관리용**). 비우면 `drug:품목명` 자동 생성 | `drug:아모디핀정5mg` |
| `updated_at` | 선택 | 갱신일. 비우면 오늘 날짜 자동 | `2026-10-12` |

> **핵심 규칙 2가지**
> 1. **`source`는 반드시** 채웁니다(근거 없는 정보 차단).
> 2. **`text`를 직접 안 써도 됩니다.** `drug_name`+`effect`+`caution` 등 항목만 채우면
>    전처리 도구가 사람이 읽는 한 문장(`text`)을 자동으로 만들어 줍니다.

### 1-3. 표준 JSONL 예시 (`drugs_sample.jsonl` 참고)

```jsonl
{"id":"drug:아모디핀정5mg","category":"drug","drug_name":"아모디핀정 5mg","ingredient":"암로디핀베실산염","amount":"5mg","effect":"본태성 고혈압과 협심증 치료","caution":"자몽주스와 함께 복용 금지","source":"식약처 의약품 제품 허가정보","updated_at":"2026-10-12"}
```

### 1-4. CSV(엑셀)로 만들 때 — 첫 줄(머리글) 예시

엑셀 첫 행에 아래처럼 한글 제목을 써도 됩니다(도구가 자동 인식):

```
의약품명, 성분명, 함량, 효능효과, 용법, 주의사항, 보관법, 출처, 분류
아모디핀정 5mg, 암로디핀베실산염, 5mg, 고혈압·협심증 치료, 1일 1회 1정, 자몽주스 금지, 실온 보관, 식약처 허가정보, drug
```

인식되는 머리글(한글/영문 모두 가능):
`의약품명·품목명·제품명→drug_name`, `성분·성분명→ingredient`, `함량·용량→amount`,
`효능·효능효과→effect`, `용법·복용법→usage`, `주의·주의사항→caution`,
`부작용→side_effect`, `보관·보관법→storage`, `생김새·성상→appearance`,
`출처→source`, `분류→category`, `아이디→id`

## 2. 전처리 도구 사용법 (`tools/drug_preprocess.py`)

> 모든 명령은 **`backend` 폴더**에서 실행합니다.
> 파이썬은 가상환경(`venv`)의 것을 쓰면 됩니다. (예: `venv\Scripts\python`)

### 2-1. 변환 — 원본 → 표준 JSONL
```bash
# 엑셀을 CSV로 저장한 뒤
python tools/drug_preprocess.py convert 내자료.csv -o knowledge/my_drugs.jsonl
```
- 실행하면 **저장 N건 / 중복제거 K건 / 건너뜀 M건(사유 포함)** 보고서가 출력됩니다.
- 식약처 API로 받은 `.json`/`.xml` 파일도 그대로 넣을 수 있습니다.

### 2-2. 검증 — 문제 없는지 확인
```bash
python tools/drug_preprocess.py validate knowledge/my_drugs.jsonl
```
- 출처 누락, 본문 비어있음, **id 중복** 등을 줄 번호와 함께 알려줍니다.

### 2-3. 병합 — 여러 파일을 하나로(중복 제거)
```bash
python tools/drug_preprocess.py merge knowledge/a.jsonl knowledge/b.jsonl -o knowledge/all.jsonl
```

## 3. RAG 등록 · 갱신 · 중복관리 (어떻게 반영되나)

### 3-1. 등록/갱신 절차
1. 변환한 `.jsonl` 파일을 `backend/knowledge/` 폴더에 둡니다. (여러 파일 가능)
2. 서버가 떠 있는 상태에서 **`POST http://localhost:8000/api/rag/reload`** 를 호출합니다.
   - (서버를 재시작해도 자동으로 다시 읽습니다.)
3. 현황은 **`GET /api/rag/status`** 로 확인합니다(문서 수·분류·출처).
4. 검색 테스트는 **`GET /api/rag/search?q=고혈압 약 주의사항`** 으로 확인합니다.

### 3-2. 중복 관리 — `id`가 기준입니다
- 같은 `id`를 가진 문서가 있으면 **나중 것이 앞의 것을 덮어씁니다(= 갱신)**.
- 즉, 기존 약 정보를 **고치려면 같은 `id`로** 다시 넣으면 됩니다.
- `id`를 비워두면 `drug:품목명` 으로 자동 생성되므로, **품목명이 같으면 자동으로 하나로** 관리됩니다.

### 3-3. 임베딩 · 벡터 반영 — 바뀐 것만 다시 계산
- RAG는 각 문서의 `text`를 **임베딩(숫자 벡터)**으로 바꿔 유사도 검색을 합니다.
- 임베딩 결과는 `knowledge/.embedding_cache.json` 에 **본문 해시 기준으로 캐시**됩니다.
- 그래서 `reload` 할 때 **내용이 바뀌지 않은 문서는 다시 임베딩하지 않습니다.**
  → 수천 건이 있어도 **새로 추가/수정한 것만** 비용·시간이 듭니다.
- (OpenAI 키가 없으면 임베딩 대신 **키워드 검색 모드**로 자동 동작 — 데모에서도 돌아감.)

## 4. 유지보수 · 확장성 — 개발사 없이 가능한 범위

### ✅ 지금 시제품에서 **제작사 제공(이미 구현됨)**
- 표준 스키마(이 문서) + 자동 변환/검증 도구(`drug_preprocess.py`)
- 외부 지식파일(`knowledge/*.jsonl`) 로딩 — **코드 수정 없이 파일만 추가**
- `id` 기준 중복제거/덮어쓰기(갱신)
- 임베딩 증분 캐시(바뀐 것만 재임베딩)
- 반영/확인 API: `reload` · `status` · `search`
- 식약처 **낱알식별정보 API** 연동(생김새·이미지로 약 식별) + 허가정보·e약은요 보강

### 🔧 추가 개발이 필요한 범위(원하실 때)
- **관리자 화면(UI)**: 지금은 파일+API 호출 방식. 웹에서 업로드→변환→반영 버튼으로.
- **자동 수집(스케줄러)**: 식약처 API를 매주 자동으로 받아 변환·반영(아래 4-1 참고).
- **대용량 벡터DB 전환**: 수십만 건↑이면 인메모리 → ChromaDB/pgvector 로 교체.
- **변경 이력/승인 워크플로**: 누가 언제 무엇을 바꿨는지 기록·되돌리기.

### 4-1. 자동화(선택) — 주기적 갱신
- 손주약방에는 이미 스케줄러(`apscheduler`, `app/agent_scheduler.py`)가 있습니다.
- 여기에 "주 1회: 식약처 API 조회 → `drug_preprocess` 변환 → `reload`" 작업을 등록하면
  **사람 개입 없이 자동 갱신**됩니다. (이 부분은 추가 개발 항목)

## 5. 자주 하는 질문

- **Q. 엑셀만 다룰 줄 아는데 가능한가요?**
  네. 엑셀로 표를 만들고 `CSV로 저장` → `convert` 한 번이면 됩니다.
- **Q. 자료를 잘못 넣었어요.**
  해당 `.jsonl` 파일을 고치거나 지우고 다시 `reload` 하면 됩니다. 원본은 그대로 보관하세요.
- **Q. 정보가 겹치면요?**
  같은 `id`(또는 같은 품목명)면 **마지막에 넣은 내용으로 자동 정리**됩니다.
- **Q. 이 폴더의 `.embedding_cache.json` 은 뭔가요?**
  임베딩 재사용 캐시입니다. 지워도 되지만(안전), 지우면 다음 `reload` 때 전부 다시 계산합니다.
